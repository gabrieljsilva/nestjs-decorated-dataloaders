# Contribution Guide

Thank you for your interest in contributing to this project! We aim to make the collaboration process simple and efficient. Please follow this guide to ensure your contribution is successful.

---

## Types of Contributions

We welcome different types of contributions, including:
- **Bug reports**
- **Suggestions for improvements or new features**
- **Documentation enhancements**
- **Code fixes and improvements**
- **General discussions**

---

## How to Report Issues

To report a problem or suggest something new, open an **issue** on GitHub following these guidelines:

1. **Check existing issues:** Before opening a new issue, make sure it has not already been reported.
2. **Choose the correct type:** Use our issue templates to properly categorize your report:
    - **Bug Report**: For technical issues.
    - **Feature Request**: To suggest improvements or new features.
3. **Provide detailed information:**
    - **Clear title:** Summarize the problem or suggestion.
    - **Detailed description:** Explain the problem or idea.
    - **Steps to reproduce:** Include instructions if it is a bug.
    - **Environment:** Specify software versions, operating system, etc.
    - **Screenshots or logs:** Whenever possible.

---

## Issue Template Structure

We use templates to make issue creation easier:

### Bug Report
```markdown
**Problem Description:**
[Clearly describe the issue.]

**Steps to Reproduce:**
1. [Step 1]
2. [Step 2]
3. [Step 3]

**Expected Behavior:**
[What should happen.]

**Environment:**
- Version:
- Operating System:

**Additional Information:**
[Include screenshots or logs if applicable.]
```

### Feature Request
```markdown
**Description:**
[Explain the feature you would like to see.]

**Motivation:**
[Why is this feature important?]

**Considered Alternatives:**
[Explain alternative solutions if applicable.]

**Additional Information:**
[Include any other relevant details if necessary.]
```

---

## Labels

To keep issues organized, we use the following labels:
- **bug**: For technical issues.
- **enhancement**: For improvements and new features.
- **documentation**: For documentation problems or improvements.
- **question**: For general questions or discussions.
- **good first issue**: Simple tasks for beginners.
- **help wanted**: Tasks that need assistance.

---

## Submitting Pull Requests (PRs)

1. **Fork the repository** and clone it locally.
2. Create a branch for your changes:
   ```bash
   git checkout -b my-contribution
   ```
3. Ensure you follow coding standards and include tests (if applicable).
4. Push your branch to your fork and open a Pull Request.
5. Clearly describe the changes in the PR and link it to the corresponding issue, if any.

---

## Expected Behavior

We expect all contributors to follow the project’s [Code of Conduct](./CODE_OF_CONDUCT.md) and maintain a welcoming and respectful environment.
